## 新增参数

| 前一个参数/新参数分组 | 参数名称 | 默认值 | 可选值 | 描述 |
|---|---|---|---|---|
| --return-hidden-states-mode | --enable-return-aux-hidden-states | False | bool flag (set to enable) | Capture auxiliary hidden states on the target model without running a speculative draft. --speculative-algorithm then only names the capture convention (EAGLE3, DFLASH or DSPARK) and is reset to None. Requests with return_hidden_states receive the concatenated aux hidden states in place of the last-layer hidden states. Sets --return-hidden-states-mode to full when unset. Requires pp_size == 1. |
| --enable-return-aux-hidden-states | --return-aux-hidden-state-layer-ids | None | Type: list of int | Target-model layer ids for the selected capture convention. These may differ from draft-checkpoint layer ids. Required for DFLASH and DSPARK; EAGLE3 defaults to the model's EAGLE3 layers. |
| --enable-decoder-swa-bounded-replay | --enable-prefill-weight-versions | False | bool flag (set to enable) | Enable returning the weight version that computed each prompt token's KV cache with responses, as meta_info['prefill_weight_versions']. |
| --deepep-config | --moe-ascend-ops-config | None | Type: str | Configuration for the ascend_ops MoE backend used by the main model and/or speculative draft as a JSON object, for example {"prefill":"alltoallv","decode":"low_latency"}. |
| --ple-offload-dir | --engram-config | None | Type: JSON object (dict) | Where the DeepSeek-V4.1 Engram tables live, as JSON: 'placement' gpu\|cpu, 'replication' none\|per_node, 'lookup' auto\|all_reduce\|reduce_scatter\|all_to_all\|peer_read; an omitted key takes the first value. See docs/advanced_features/engram. |
| --hicache-storage-prefetch-retry-max-attempts | --hicache-storage-key-scheme | rank-suffix | rank-suffix, unified | How L3 storage object keys encode what an object holds. 'rank-suffix' (legacy): keys carry the writer's tp/pp/cp rank, so only a bit-identical topology can reuse the cache. 'unified': keys carry topology-free grid coordinates (a namespace digest plus absolute layer and head-group indices), so any topology whose shards tile the same grid shares one cache. Implies --hicache-mem-layout page_unified and --hicache-io-backend kernel. Currently supported by the file backend for one chunk per page. |
| --hicache-storage-key-scheme | --hicache-storage-head-partition | None | Type: int | KV heads per L3 chunk under --hicache-storage-key-scheme unified. A FLEET-WIDE agreement, not a local tuning knob: it fixes chunk boundaries, and the boundaries are part of the key namespace. Set it to total_kv_heads divided by the lcm of the attention-TP sizes in the fleet, so every member's local head count is a whole number of chunks. Unset, each deployment keys to its own head count and shares only with its own TP size. MLA-family models replicate KV across ranks and ignore it. |
| --hicache-storage-head-partition | --hicache-storage-layer-partition | None | Type: int | Layers per L3 chunk under --hicache-storage-key-scheme unified; the pipeline-parallel counterpart of --hicache-storage-head-partition and equally fleet-wide. Every stage must START on a multiple of it; only the final stage may end short, and that remainder forms the last chunk. Unset, each stage stores its own layer range and shares only with an identical split. |
| --cp-strategy | --cp-kv-layout | None | dynamically registered | KV storage layout for prefill CP; omitted keeps replicated KV storage. |
